# CPU budget и BGE — 2026-09-15

## Что исправлено

`MEMORY_TORCH_THREADS` теперь задаёт `OMP_NUM_THREADS` и
`OPENBLAS_NUM_THREADS` **до импорта PyTorch**, затем ограничивает PyTorch и уже
загруженные BLAS-библиотеки. Бюджет применяется при загрузке CE/Flag reranker,
NLI, bounded reranker, SentenceTransformer embeddings и при калибровке.
Это настройка процесса; значение MEMORY_TORCH_THREADS имеет приоритет над
унаследованными OMP/OPENBLAS значениями. Для изменения нужен перезапуск процесса.
Если стороннее приложение импортировало PyTorch раньше, ранняя настройка уже
не гарантируется: задайте переменные при запуске такого приложения.

Нативные стеки GDB показали пять дополнительных `gomp_thread_start` потоков.
Поздние `torch.set_num_threads(1)`, BLAS limits и даже all-pools limits показывали
один поток в API, но не устраняли эти рабочие потоки в использованной сборке.
Ранняя переменная окружения устранила их; то же подтверждено настоящим runtime
loader без внешнего задания OMP_NUM_THREADS.

## Измерение

Linux aarch64, Docker, PyTorch2.14.0+cpu, BGE-v2-m3,10коротких пар,20прогретых
повторений. Сборка модели float32; download/load не входят в замер.

| Вариант | p50, мс | p95, мс | CPU p50, мс |
|---|---:|---:|---:|
| Только поздний Torch limit1 | 773,68 | 813,07 | 2256,05 |
| INT8 QNNPACK | 2040,37 | 2081,54 | 2074,27 |
| Поздний BLAS limit1 | 780,88 | 880,23 | 2265,07 |
| Ранний OMP limit1, контроль | 2117,64 | 2132,13 | 2116,26 |
| Исправленный runtime loader, limit1 | 2132,15 | 2179,29 | 2132,41 |

В финальном runtime за20запросов CPU расходовал только основной поток
(42,68с по `/proc`, порог учёта0,01с). Отношение CPU/времени ожидания стало
около1 вместо2,9. Это ограничение параллельной нагрузки, **не ускорение BGE**.
Работы на запрос почти столько же; ожидание длиннее. Порядок результатов
float32 сохранён, численные расхождения порядка1e-9. INT8 изменил порядок
и проиграл по задержке, поэтому в runtime не включён.

**Порог200мс не достигнут.** Для выпуска сохранён быстрый режим без тяжёлого
reranker по умолчанию. Ограничитель времени bounded reranker остаётся отдельной
защитой с возвратом исходного порядка. Нулевая нагрузка CPU во время вычислений
не заявляется. Эти тяжёлые измерения выполнены на Linux aarch64, не на всех ОС.

Артефакты: `bge-cpu-*.json`, `bge_cpu_probe.py`, `bge-native-backtrace.log`.
Первый py-spy native profiler завис в tracing stop; его тестовый контейнер
остановлен, журнал сохранён в `bge-profiler-failure.log`. Его время не считается
производительностью модели. Успешная трассировка выполнена через GDB.

Использованы официальные описания [PyTorch quantization](https://pytorch.org/blog/quantization-in-practice/)
и [threadpoolctl](https://github.com/joblib/threadpoolctl); сравнение выше измерено
локально, а не взято из документации.
