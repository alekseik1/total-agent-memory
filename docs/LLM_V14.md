# LLM и CPU — настройки 14.0.0

Основной выбор: `MEMORY_LLM_PROVIDER=ollama|openai|openai-compatible|anthropic`. Модель задаётся `MEMORY_LLM_MODEL`, ключ — `MEMORY_LLM_API_KEY`, базовый адрес — `MEMORY_LLM_API_BASE`. Для Ollama используется также `OLLAMA_URL`.

Для OpenAI-compatible сервера адрес и модель обязательны. Ключ можно не задавать, если сам endpoint допускает запросы без авторизации. Ключ из `OPENAI_API_KEY` в этот режим автоматически не переносится. Обычный `openai` по-прежнему требует ключ. Поддерживается протокол Chat Completions; произвольный несовместимый HTTP API требует отдельного адаптера. Для структурированных ответов endpoint должен поддерживать JSON Schema.

Генерация эпизодов, краткие описания ingestion, HyDE и LLM reranking теперь используют общий провайдер. Для Ollama остаются отдельные `HYDE_MODEL` и `RERANKER_MODEL`; без них используется общая модель. Жёсткий выбор 32B для эпизодов и описаний удалён. `MEMORY_LLM_ENABLED=false` запрещает эти вызовы.

Описания изображений используют тот же выбранный провайдер: Ollama, OpenAI-compatible или Anthropic. Указать отдельный `MEMORY_VISION_MODEL`, поддерживающий изображения; без него автоматический вызов большой vision-модели не производится. PNG/JPEG/GIF/WebP определяются по содержимому, размер ограничен6MiB; другие форматы сначала конвертировать. `MEMORY_LLM_ENABLED=false` запрещает и этот маршрут. Адаптеры проверены транспортными регрессиями; доступность конкретной пользовательской модели требует её подключения.

## Docker

Стандартный `docker-compose.yml` сохраняет локальный стек с Ollama. Общие настройки провайдера и `MEMORY_EMBED_THREADS` передаются MCP, dashboard и фоновым службам через `.env`.

Если модель работает вне этого Compose-стека, сначала задать её провайдер, адрес, модель и необходимые ключи в `.env`, затем использовать оба файла:

```sh
docker compose -f docker-compose.yml -f docker-compose.external.yml config --services
docker compose -f docker-compose.yml -f docker-compose.external.yml up -d --build
```

Внешний вариант включает MCP, dashboard, reflection и scheduler; Ollama/model-init не запускаются. `localhost` внутри контейнера обозначает сам контейнер. Адрес внешней модели должен быть доступен контейнеру. Проверка `config --services` не подтверждает доступность модели и не заменяет запрос к ней. Эти команды подготовлены для пользователя; действующий стек в ходе разработки не запускался и не обновлялся.

Нужен Docker Compose с поддержкой `!reset`; использованный для проверки Compose — 5.5.1. [Правила объединения Compose](https://docs.docker.com/reference/compose-file/merge/).

## Ограничение CPU

`MEMORY_EMBED_THREADS=1` по умолчанию ограничивает потоки каждой FastEmbed-модели во всех четырёх путях её загрузки: сервер, embedding provider, reembed, fact index. Значение должно быть положительным целым. Для серверной пакетной индексации его можно увеличить после измерения CPU и задержек.

`MEMORY_TORCH_THREADS=1` ограничивает intra-op CPU-потоки PyTorch при загрузке NLI и CrossEncoder. Значение должно быть положительным целым. Настройка действует на процесс PyTorch, не на весь сервер. Лимиты OpenMP/BLAS устанавливаются до импорта PyTorch; после изменения настройки перезапустите процесс. Финальная проверка BGE на Linux ARM64 с ранним ограничением потоков дала p95 2179,29 мс при бюджете 200 мс. Ограничение параллельной нагрузки увеличило задержку; это не ускорение. См. [измерения CPU](benchmarks/grounded-v14/CPU_RESULTS.md).

Это ограничения моделей, не общий лимит CPU всех процессов. Они не ограничивают Ollama, число клиентов и фоновых процессов. Нулевая нагрузка всей системы не заявляется.
